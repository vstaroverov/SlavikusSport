# Slavikus Sport

Slavikus Sport — персональный планировщик тренировок и дневник результатов. В нём можно составить программу, назначить тренировку на дату, записать выполненные упражнения и увидеть свой прогресс. Приложение рассчитано на использование на одном устройстве: данные хранятся локально, а для переноса служит JSON-копия.

Доступны две пользовательские версии с общими экранами и данными одного формата:

| Версия | Как открыть | Особенность |
| --- | --- | --- |
| **Android** | [Страница в RuStore](https://www.rustore.ru/catalog/app/ru.slavikus.sport) | Во время начатого упражнения «Бег» GPS записывает пробежку, в том числе при свёрнутом приложении. |
| **Веб-приложение для iPhone** | [Открыть в Safari](https://vstaroverov.github.io/SlavikusSport/) → «Поделиться» → «На экран Домой» | Работает как приложение с ярлыка. Дистанция и время бега вводятся вручную; Android GPS-трекер здесь недоступен. |

В репозитории также есть проект Capacitor для iOS. Пользовательская версия для iPhone сейчас распространяется как веб-приложение, а не через App Store.

## Что умеет приложение

**Программа и календарь.** Создавай тренировки с нуля или из шаблона, добавляй упражнения, меняй их порядок и плановые значения. Календарь назначает тренировку на конкретный день или оставляет день отдыха. На главном экране видны план на сегодня и быстрые переходы к основным разделам.

**Тренировка.** Запускай и ставь занятие на паузу, отмечай выполненные подходы и пропускай ненужные. Для бега и плавания записываются дистанция и время; для разминки и заминки — сам факт выполнения; для виса — секунды. После завершения приложение показывает результат и добавляет выполненное в лог. Пропущенные упражнения и пустые нулевые результаты в лог не попадают.

**Справочник упражнений.** У упражнения задаются название, категория и тип измерения. Поддерживаются повторения, повторения с дополнительным весом, секунды, дистанция и выполнение без числового показателя. Эти настройки определяют поля в программе, во время занятия и при ручном добавлении записи в лог.

**Лог и статистика.** Историю можно пополнять после тренировки или вручную, редактировать записи и делиться ими, включая прикреплённое фото. В статистике видны последние и лучшие результаты: повторения показаны столбцами, а для упражнений с весом поверх них отображается динамика веса. Для дистанции и времени используется история результатов.

**Обмен.** В разделе «Тренер» можно показать другу QR-код установки или отправить ссылку. Выбранные тренировки экспортируются в JSON-файл; получатель загружает этот файл в свою программу. Это обмен шаблонами тренировок, а не автоматическая синхронизация истории между устройствами.

## Данные и резервная копия

Профиль, программа, календарь и лог сохраняются на устройстве в IndexedDB. Данные из старых версий приложения переносятся из `localStorage`. Серверной учётной записи и синхронизации между Android и веб-версией нет: у каждой установки свой набор данных.

В **Профиль → Резервная копия** можно скачать полный JSON-файл, проверить его состав и восстановить данные. Полная копия **заменяет** текущие локальные данные; файл обмена тренировками **добавляет** тренировки в программу. Поддерживается загрузка резервных копий старого формата, а при восстановлении из лога удаляются пустые нулевые записи. Перед переносом на другое устройство сохрани свежую копию и проверь, что файл действительно появился в «Загрузках» или «Файлах».

## Запуск проекта

### VK Mini App (подготовка)

Отдельная сборка VK Mini App использует те же экраны, программу, лог, статистику и JSON-копию. Она запускает VK Bridge, но не регистрирует PWA service worker. Android GPS-трекер внутри VK недоступен: дистанция и время бега вводятся вручную. Данные хранятся локально в браузере/клиенте VK и не синхронизируются между устройствами. Для переноса используй **Профиль → Скачать копию** и **Восстановить**. Встроенный браузер VK может по-разному обрабатывать скачивание и выбор файлов; это нужно проверить на настоящих iPhone и Android после тестовой публикации.

```bash
npm run build:vk
cd vk-dist
node ../server.js
```

Локальная проверка доступна по адресу `http://localhost:4173`. Приложение VK имеет ID `54813678` и короткий адрес [vk.com/app54813678](https://vk.com/app54813678). Конфигурация `vk-hosting-config.json` уже содержит этот ID и каталог `vk-dist/`. Для загрузки на [хостинг VK Mini Apps](https://github.com/VKCOM/vk-miniapps-deploy) нужен доступ разработчика к приложению и токен публикации. Сначала загрузи тестовую версию, проверь её внутри VK на телефоне и компьютере, затем выпускай для пользователей. Ключи и токены в Git не добавляй. [VK Bridge](https://github.com/VKCOM/vk-bridge) включён в сборку локальным файлом вместе со своей лицензией MIT.


Нужен Node.js с npm. После клонирования репозитория:

```bash
npm ci
npm run dev
```

Локальный сервер откроется по адресу `http://localhost:4173`. Полезные команды:

| Команда | Назначение |
| --- | --- |
| `npm test` | Проверить логику программы, лога, хранения данных и экранов. |
| `npm run build` | Собрать веб-файлы в `www/` для Capacitor. |
| `npm run build:pages` | Собрать публикуемую веб-версию в `docs/`. |
| `npm run android:sync` | Собрать веб-файлы и синхронизировать Android-проект. |
| `npm run android:apk` | Собрать release APK в папку `apk/`. |

Для обновления уже опубликованного Android-приложения нужен **тот же ключ подписи**, которым подписана версия в RuStore. Настройки подписи читаются из локального `android/release-signing.properties`; ключ и пароли не входят в репозиторий. Без них release APK будет неподписанным и не подойдёт для обновления опубликованного приложения. Android-проект находится в `android/`, исходный код приложения — в `src/`, правила интерфейса — в `design-system-v-star-group/`, а материалы для RuStore — в `rustore-assets/`.
