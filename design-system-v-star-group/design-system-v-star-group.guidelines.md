# V-STAR Group · Product UI 2.6.0

Для ai-gen-content действуют [согласованные правила 2.3.0](design-system-v-star-group.product-decisions.md): только тёмная тема и минимальный согласованный состав экранов. Упоминания светлой темы ниже описывают исторические возможности библиотеки, а не разрешение использовать их в продукте.

Для Slavikus Sport создан [отдельный раздел с правилами и компонентами приложения](design-system-v-star-group.sport.md). Он использует общее ядро без переноса сценариев ai-gen-content.

Общее ядро для продуктов группы. Специфичные сценарии «Ритма» в эту версию не добавлены. Примеры используют проекты, участников и задачи; backend, авторизация, биллинг и реальные интеграции не реализуются дизайн-системой.

## Каталоги

- `design-system-v-star-group.html` — базовые элементы бренда.
- `design-system-v-star-group.products.html` — продуктовый каркас, сложные формы, таблицы, аналитика, шаблоны и состояния.
- Для продуктового каталога нужен HTTP-сервер: используются ES-модули. Из корня проекта: `node design-system-v-star-group/design-system-v-star-group.preview.mjs`, затем `/design-system-v-star-group.products.html` на `http://127.0.0.1:4178`.
- Демо не отправляет данные и не хранит их между перезагрузками. Экспорт CSV скачивает только выбранные демонстрационные строки. Файлы читаются локально.

## Архитектура токенов

Единственный редактируемый источник: `design-system-v-star-group.tokens.source.json`.

1. Бренд: `brand-lime`, `brand-cyan`, `brand-blue`.
2. Семантика: `bg`, `surface`, `text`, `muted`, `danger`, `success`, `selected`, `hover`, `active`.
3. Компоненты: `button-primary-bg`, `field-bg`, `control-height`, `table-cell-padding`.
4. Темы и плотность: `themes.light`, `densities.compact` переопределяют смысловые значения.

Команда `node design-system-v-star-group.build-tokens.mjs` генерирует CSS и JSON. Не редактировать производные файлы вручную. Ключи JSON содержат CSS-значения и ссылки `var(...)`; это собственный переносимый формат, не заявленная совместимость с DTCG/Figma Tokens.

Светлая тема — продуктовое расширение исходного бренда. Лаймовый фон CTA сохраняется; лаймовые текстовые акценты заменяются тёмным зелёным. Недостаточно просто инвертировать фон. Изменение темы должно применяться также к portal-контейнерам, графикам и диалогам.

Уровни: основной контент → sticky 20 → меню 30 → overlay 40 → toast 50. Нативные dialog/popover используют браузерный top layer, который выше обычного z-index. Важную ошибку внутри dialog показывать внутри него, а не за ним во внешнем toast.

## Геометрия и адаптация

| Среда | Правила |
| --- | --- |
| Desktop ≥1100 px | Боковая навигация, рабочая область, 12-колоночная концептуальная сетка |
| Tablet 761–1099 px | Узкий sidebar, формы по доступной ширине, 8 колонок |
| Mobile ≤760 px | Меню перестраивается над контентом, формы и split-pane в одну колонку, 4 колонки |
| Touch | Высота действия не менее 44 px, включая compact; hover не обязателен |
| Увеличение текста | Не фиксировать высоту текстовых карточек; названия переносить |

Плотность comfortable: поля 46 px, ячейки 16×20 px. Compact: поля 36 px, ячейки 10×14 px; compact предназначен прежде всего для desktop. Смена плотности не меняет иерархию и смысл.

Широкая таблица прокручивается внутри собственного контейнера. Для экранов, где важнее чтение одного объекта, использовать список карточек или split-pane. Не скрывать основные действия только ради компактности.

## Контракт состояний

| Состояние | Что сохраняется | Обязательное поведение |
| --- | --- | --- |
| Default / hover / pressed / focus | Смысл, размер и текст | Видимый focus; pressed не сдвигает layout |
| Selected | Выбор пользователя | Семантика aria-selected / aria-pressed / checked |
| Disabled | Подпись и объяснение | Причина в доступном тексте, не только tooltip |
| Readonly | Видимость значения | Можно выделить и скопировать |
| Initial loading | Структура экрана | Skeleton + текст; не показывать фиктивные метрики |
| Refreshing | Предыдущие данные | Не заменять рабочий экран пустым skeleton |
| Empty | Контекст раздела | Причина и полезное первое действие |
| No results | Запрос и фильтры | Предложить изменить или сбросить фильтры |
| Error | Ввод пользователя | Локальная ошибка рядом с полем + summary при нескольких ошибках |
| Success | Результат | Сообщение описывает завершённое действие |
| No permission | Разрешённые данные | Объяснить недостающую роль; не обещать выдачу доступа |
| Offline | Локальная/последняя доступная версия | Не объявлять сохранение на сервере успешным |
| Session expired | Безопасный черновик, если продукт это поддерживает | Предложить повторный вход |
| Dirty | Текущий ввод | Сохранить / отменить / продолжить редактирование |
| Conflict | Обе версии | Сравнение и явный выбор; без тихой перезаписи |
| Partial | Успешные результаты | Показать проблемные объекты отдельно |
| Unknown | Идентификатор операции | Сначала проверка статуса, без слепого повторения |
| Maintenance | Объяснение и доступные разделы | Не обещать время восстановления без данных |

Наличие UI-состояния не означает, что продукт автоматически сохраняет черновики, умеет offline, повторять запросы или сверять операции. Эти гарантии должен предоставить его backend. В каталоге действия состояния обозначены как демо.

Для аналитики различать: ноль, отсутствие измерений, недостаточный объём выборки, недоступность метрики. Подписи должны объяснять причину. Не вычислять тренд по отсутствующим значениям.

## Поведение компонентов

- **Combobox:** фокус остаётся в поле, ArrowUp/Down выбирают активную опцию, Enter подтверждает, Escape закрывает. Смена запроса сбрасывает активную опцию. В React value содержит идентификатор, а не подпись.
- **MultiSelect:** понятная групповая подпись и выбранные значения; нативные checkbox доступны с клавиатуры.
- **Меню/Popover:** native popover закрывается снаружи и Escape; доступен обычный trigger. Это немодальный dialog с кнопками/ссылками, а не ARIA menu с неполной клавиатурной моделью.
- **Modal/Drawer:** блокировка фонового фокуса, закрытие Escape, возврат к инициатору. Опасное действие не получает начальный фокус. Не заменять проверенные существующие диалоги новым примитивом только ради оформления.
- **Tabs:** активная вкладка единственная в Tab-последовательности; ArrowLeft/Right, Home, End; каждая панель связана с вкладкой.
- **Таблица:** смена фильтра сбрасывает выбор в демо; при переносе это правило явно согласовать с продуктом. Выбор страницы и выбор всех результатов — разные действия. Сортировка озвучивается через aria-sort.
- **Файлы:** до загрузки проверять формат/размер, после — ответ сервера. В каталоге прогресс отражает локальное чтение файла, не сетевую загрузку. React FileUpload принимает progress/error от вызывающего кода.
- **Уведомление:** не перекрывает главное действие, имеет явное закрытие. Срочные ошибки — в контексте операции, не только toast.
- **Формы:** видимые labels, связь помощи/ошибки с полем, сохранение ввода, проверка диапазонов. В каталоге используется нативная валидация плюс проверка дат.

## Текст, числа и иконки

- Кнопка называет действие: «Сохранить», «Добавить контакт», «Проверить статус». Избегать непонятного «ОК».
- Ошибка: что произошло → что сохранилось → что можно сделать.
- Не использовать технические коды вместо объяснения; ID операции допустим в раскрываемых деталях.
- Валюта и единицы всегда указаны; форматировать через Intl.NumberFormat, даты — Intl.DateTimeFormat с явным timeZone.
- Не помещать критичное значение только в tooltip. Длинный текст переносить; сокращённый давать раскрыть в деталях.
- Иконки 20/24 px, stroke 1.75, без emoji. Декоративные SVG скрыты от скринридера; icon-only кнопка получает aria-label.
- SVG-символы каталога — общий набор навигационных действий, логотип не заменяют. В существующем продукте можно сохранить Lucide с той же геометрией.

## React API

`design-system-v-star-group.react.tsx` экспортирует Theme, Icon, Button, Input, Textarea, Select, Field, Checkbox, Radio, Switch, Card, Badge, Alert, EmptyState, Skeleton, Progress, PageHeader, Toolbar, SaveBar, AppShell, SplitPane, Dialog, Tabs, Combobox, MultiSelect, PasswordField, NumberField, DateRange, TagInput, FileUpload, DataTable, Pagination, Accordion, Toast, Popover, Steps, Breadcrumbs, Timeline, Repeater, BarChart.

Требуется React 19. Компоненты не вызывают API и не содержат моделей проектов. Сложные значения контролируются через value/onValueChange, open/onOpenChange, selected/onSelectionChange. Native props передаются для Button/Input и других базовых полей, включая ref в React 19.

```tsx
import { Theme, Field, Input, Button } from './design-system-v-star-group.react';
import './design-system-v-star-group.tokens.css';
import './design-system-v-star-group.css';
import './design-system-v-star-group.products.css';

<Theme theme="dark" density="comfortable">
  <Field label="Название" error={errors.name} required>
    {field => <Input {...field} value={name} onChange={e => setName(e.target.value)} />}
  </Field>
  <Button variant="primary" busy={saving} onClick={existingSaveHandler}>
    {saving ? 'Сохранение…' : 'Сохранить'}
  </Button>
</Theme>
```

Существующее приложение уже содержит примитивы Base UI/shadcn. Для них предпочтителен `design-system-v-star-group.adapter.css` под `.vsg.vsg-primitives`: он меняет токены и геометрию, не handlers и не focus management. Сначала проверить в изолированном компоненте; специфичные классы существующего продукта могут требовать отдельной стилизации. Адаптер не подключён к приложению автоматически.

При portal передавать тему в отдельный `.vsg`-контейнер. У React Dialog предусмотрены theme/density. Готовые templates каталога — reference compositions, а не модуль авторизации или биллинга.

## Проверки и сопровождение

Из корня проекта:

```sh
node design-system-v-star-group/design-system-v-star-group.build-tokens.mjs --check
node --test design-system-v-star-group/design-system-v-star-group.test.mjs
node app/node_modules/typescript/bin/tsc -p design-system-v-star-group/design-system-v-star-group.tsconfig.json
```

TypeScript-конфигурация использует уже установленные типы React соседнего приложения только для локальной проверки. При переносе библиотеки настроить собственные React dependencies/type resolution.

Автоматические проверки: фильтрация/сортировка/границы пагинации, валидация файлов/дат, контраст ключевых пар в двух темах, ARIA- и файловые ссылки, согласованность токенов, SSR-smoke React-компонентов. SSR не заменяет интерактивный браузерный тест.

Ручная приёмка:

1. Desktop 1440 px, tablet 900 px, mobile 390 px; обе темы, обе плотности.
2. Масштаб 200%, длинные строки, ошибки, пустые данные.
3. Tab/Shift+Tab, combobox, tabs, Escape, возврат фокуса после dialog.
4. Screen reader: названия полей, ошибки, mixed checkbox, график и таблица.
5. Reduced motion, coarse pointer, темы в portal-контейнерах.
6. После интеграции — реальные действия продукта и его тесты.

В текущей среде браузер для автоматизированной визуальной проверки недоступен. Матрица визуальной приёмки остаётся открытой; полная сертификация доступности не заявляется.

Версии: patch — исправление без изменения API, minor — совместимый новый компонент/вариант, major — несовместимое изменение токенов или контрактов. В каждом изменении обновлять changelog, примеры, токены и проверки. Удаляемые параметры сначала помечать deprecated с заменой.

## Что намеренно не входит

Продуктовые функции «Ритма»; настоящая авторизация и выдача прав; подключение внешних аккаунтов; оплата и списания; offline-синхронизация и хранение черновиков; полноценные rich-text/canvas/tree/kanban редакторы. Для специализированных будущих продуктов эти блоки разрабатываются как расширения общего ядра, а не обещаются одной универсальной кнопкой.
